# Модель угроз SkillTrap

## Кого защищаем

Пользователя ИИ-агента, который ставит скил из интернета: репозитория, архива, маркетплейса.
Установка скила — это, по сути, запуск чужого кода с правами пользователя, но выглядит она
как «добавить файл с инструкцией».

## Что ловим

| Угроза | Как проявляется | Как ловим |
|---|---|---|
| Кража секретов | чтение `~/.env`, `~/.ssh/id_rsa`, `~/.aws/credentials`, токенов | `openat` по пути приманки -> CRITICAL |
| Вынос секрета наружу | значение секрета уходит в аргументы другой программы или в сеть | уникальное `CANARY-<uuid>` в аргументах вызова -> CRITICAL |
| Сетевая активность | `connect()`, запуск `curl`/`wget`/`nc` | `connect` по AF_INET, `execve` сетевых утилит -> HIGH |
| Закрепление в памяти агента | дописывание `CLAUDE.md`, `AGENTS.md`, `.bashrc`, `.profile` | запись по этим путям -> HIGH |
| Скрытая нагрузка (SkillCloak) | код лежит в папке с точкой, статические сканеры туда не смотрят | loader ищет и в скрытых папках, static_checks помечает -> INFO + поведение |
| Порча и заметание следов | удаление и переименование файлов, запись вне рабочей папки | `unlinkat`, `renameat2`, запись вне `/skill` -> MEDIUM |
| Спрятанный текст | инструкции, скрытые невидимыми символами Unicode | static_checks -> LOW |

## Что НЕ ловим

1. **Вредоносные инструкции в тексте SKILL.md (prompt injection).** Их исполняет агент, а не
   интерпретатор, поэтому в strace ничего не появится. Это задача этапа 2 из roadmap —
   запуск агента внутри песочницы с нейтральной задачей.
2. **Отложенное срабатывание.** Скил может вести себя тихо при первом запуске и активироваться
   позже: по дате, по числу запусков, по наличию определённого файла. Один прогон это не покажет.
3. **Определение песочницы.** Скил может заметить, что он в контейнере (по `/proc`, по имени
   пользователя, по отсутствию сети), и не показать вредного поведения.
4. **Скрипты на других языках.** Сейчас запускаются только `.py` и `.sh`. `.js`, бинарники и
   компилируемый код — в roadmap.
5. **Вред через зависимости.** Скил может тянуть пакет, который вредит при установке;
   у песочницы нет сети, поэтому такая установка просто не состоится и останется незамеченной.
6. **Действия, не попадающие в список трассируемых вызовов.** strace пишет только
   `openat/open/execve/connect/unlinkat/unlink/renameat2/rename`. Частично это покрывает
   `fsdiff`: он сравнивает хеши файлов и не зависит от набора syscall'ов.

## Безопасность самой проверки

- Контейнер: `--network none`, `--user 1000:1000`, `--memory 256m`, `--cpus 1.0`,
  `--pids-limit 128`, `--cap-drop ALL`, `--security-opt no-new-privileges`,
  таймаут 30 секунд снаружи и внутри.
- Добавляется единственная привилегия `--cap-add SYS_PTRACE` — она нужна strace.
- В контейнер монтируется **копия** скила во временной папке; оригинал на хосте не меняется.
- Скрипты проверяемого скила никогда не выполняются на хост-машине.
- Приманки — только сгенерированные значения `CANARY-<uuid4>`. Настоящих ключей в репозитории нет;
  тест `test_template_has_no_real_secrets` следит за этим.
- Фикстуры в `fixtures/malicious/` только **имитируют** атаки: читают приманки, пишут файлы
  внутри песочницы, стучатся на `127.0.0.1`. Никакой реальной отправки данных и никаких
  загрузок из интернета.

## Остаточный риск

Побег из контейнера через уязвимость ядра или Docker теоретически возможен. Для учебного
проекта это принято как допустимый риск; в продакшене стоило бы добавить gVisor или отдельную
виртуальную машину.
