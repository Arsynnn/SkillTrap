# Архитектура SkillTrap

## Конвейер

```
            ┌──────────┐
 SKILL.md ─▶│  loader  │─ SkillInfo (имя, описание, список скриптов, в т.ч. в скрытых папках)
            └────┬─────┘
                 │
            ┌────▼─────┐
            │ canaries │─ CANARY-<uuid> на каждый запуск + fake_home из шаблона
            └────┬─────┘
                 │
            ┌────▼──────────────────────────────┐
            │ sandbox/runner (docker run)       │  --network none, --user 1000,
            │   strace -f -tt -s 256 -o ...     │  --memory 256m, --pids-limit 128,
            │   <python|bash> /skill/<script>   │  --cap-drop ALL, timeout 30 c
            └────┬──────────────────────────────┘
                 │  лог strace + stdout/stderr + код выхода
            ┌────▼─────────┐        ┌──────────┐
            │ trace_parser │        │  fsdiff  │ хеши fake_home до/после
            └────┬─────────┘        └────┬─────┘
                 │ list[TraceEvent]      │ FsChanges
            ┌────▼───────────────────────▼─────┐      ┌────────────────┐
            │             rules                │◀─────│ static_checks  │ LOW/INFO
            └────┬─────────────────────────────┘      └────────────────┘
                 │ list[Finding]
            ┌────▼─────┐
            │  report  │─ вердикт SAFE / SUSPICIOUS / MALICIOUS + доказательства
            └──────────┘
```

Оркестрирует всё `skilltrap/scan.py::scan_skill()`; `cli.py` и `eval/run_eval.py` — два
разных интерфейса к одной и той же функции.

## Модули

| Модуль | Отвечает за |
|---|---|
| `models.py` | pydantic-модели: `SkillInfo`, `Canary`, `TraceEvent`, `ScriptRun`, `Finding`, `FsChanges`, `Report` |
| `loader.py` | чтение SKILL.md, валидация frontmatter, поиск `.py`/`.sh` **включая скрытые папки** |
| `canaries.py` | генерация приманок, подготовка fake_home, списки путей-приманок и путей закрепления |
| `sandbox/Dockerfile` | образ: python + bash + strace, пользователь uid 1000 |
| `sandbox/runner.py` | сборка образа, подготовка workspace, `docker run` с ограничениями |
| `trace_parser.py` | строки strace -> `TraceEvent`, склейка `<unfinished>`/`<resumed>` |
| `fsdiff.py` | снимок sha256 по fake_home и сравнение до/после |
| `rules.py` | события + изменения файлов -> находки с уровнем серьёзности |
| `static_checks.py` | невидимый Unicode, base64-блобы, исполняемые файлы в скрытых папках |
| `report.py` | вывод: терминал (rich), Markdown, JSON |
| `scan.py` | сам конвейер |
| `cli.py` | `skilltrap scan`, `skilltrap eval` |

## Почему так

**Почему поведение, а не статика.** Статический сканер видит только текст файлов. Приём
SkillCloak прячет нагрузку в `.git/` и распаковывает её при запуске — для статики файл выглядит
безобидно. Запуск в песочнице показывает фактические системные вызовы.

**Почему приманки уникальны.** Значение `CANARY-<uuid4>` генерируется заново на каждый запуск.
Если такая строка появилась в аргументах `execve`, это не совпадение: секрет прочитали именно
сейчас и передали дальше.

**Почему `--network none`.** Соединение не должно состояться ни при каких условиях. Но сам вызов
`connect()` strace записывает до того, как ядро его отклонит, — попытка видна, а вреда нет.

**Почему копия скила.** В контейнер монтируется копия во временной папке, а не оригинал:
скрипты проверяемого скила не могут изменить файлы на хосте.

**Почему правила смотрят на конкретные пути.** Интерпретатор Python при старте открывает сотни
системных файлов. Реакция на любой `openat` дала бы отчёт из тысячи строк, поэтому правила
привязаны к путям приманок, файлам закрепления и конкретным действиям.

## Коды выхода CLI

| Код | Значение |
|---|---|
| 0 | SAFE |
| 1 | SUSPICIOUS |
| 2 | MALICIOUS |
| 3 | ошибка: нет Docker, скил не читается, песочница не запустилась |
