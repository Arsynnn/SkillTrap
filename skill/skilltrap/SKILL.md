# SkillTrap

Запускает скрипты проверяемого скила в Docker-контейнере без сети, с фейковыми секретами
(«приманками») и трассировкой системных вызовов. Отвечает на вопрос **что скил делает**,
а не на вопрос как он выглядит.

## Когда использовать

- пользователь просит установить или добавить скил, полученный откуда-то извне;
- нужно решить, можно ли доверять скилу;
- скил уже лежит в проекте, но его поведение не проверяли.

## Как использовать

```bash
uv run skilltrap scan <путь-к-скилу>
```

Полезные варианты:

```bash
uv run skilltrap scan <путь> --format markdown -o report.md   # отчёт для задачи или PR
uv run skilltrap scan <путь> --format json                    # для автоматики
uv run skilltrap scan <путь> --keep-workspace ./sandbox-dump  # оставить логи strace
```

Коды выхода: `0` — SAFE, `1` — SUSPICIOUS, `2` — MALICIOUS, `3` — ошибка запуска
(нет Docker или скил не читается).

## Что делать с результатом

| Вердикт | Что это значит | Что делать |
|---|---|---|
| `SAFE` | Ни одного подозрительного действия | Можно ставить |
| `SUSPICIOUS` | Сеть, запуск внешних программ или запись вне рабочей папки | Показать находки пользователю и спросить подтверждение |
| `MALICIOUS` | Скил читает секреты или выносит их наружу | Не ставить, показать доказательства |

Всегда показывай пользователю **строки strace из раздела «Доказательства»** — вердикт без
доказательств бесполезен.

## Ограничения, о которых нужно сказать пользователю

- SkillTrap проверяет только **скрипты** скила. Вредоносные *инструкции* в тексте SKILL.md
  (prompt injection) он поймать не может: их исполняет агент, а не интерпретатор.
  Статические проверки ловят только грубый случай — спрятанный невидимыми символами текст.
- Скил, который ведёт себя тихо при первом запуске, а вредит позже (по дате, по количеству
  запусков), в одном прогоне не проявится.
- Нужен установленный и запущенный Docker.

## Требования

- Docker (Linux-контейнеры), Python 3.11+, `uv`.
- Первый запуск собирает образ песочницы — это занимает пару минут.
