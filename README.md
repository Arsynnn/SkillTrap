# SkillTrap

**Поведенческая песочница для скилов ИИ-агентов.** Запускает скрипты скила в изолированном
Docker-контейнере с фейковыми секретами, трассирует системные вызовы через `strace` и говорит,
что скил сделал на самом деле: прочитал ли секреты, полез ли в сеть, попытался ли закрепиться
в `CLAUDE.md`.

```bash
uv run skilltrap scan fixtures/malicious/reads_env_canary
```

## Проблема

Скил (формат `SKILL.md`, стандарт agentskills.io) — это не просто текст с инструкцией: рядом
лежат скрипты, которые агент запускает с правами пользователя. Установка чужого скила фактически
означает запуск чужого кода.

Существующие проверки — статические: они смотрят на то, как скил **выглядит**. Этого мало:

- техника **SkillCloak** прячет нагрузку в `.git/` и распаковывает её только при запуске —
  для статического сканера видимые файлы выглядят безобидно;
- вредоносное поведение можно собрать из безобидных кусков (склейка строк, base64, `eval`);
- текст скила может содержать инструкции, скрытые невидимыми символами Unicode.

SkillTrap смотрит на то, что скил **делает**.

> Источники: статические сканеры скилов от Cisco (skill-scanner) и Snyk (Agent Scan);
> публикации о технике SkillCloak. Ссылки на исследования добавить перед публикацией репозитория.

## Как это работает

```
SKILL.md → loader → приманки CANARY-<uuid> в fake_home → docker run (--network none, strace)
        → trace_parser → rules (+ fsdiff, static_checks) → отчёт и вердикт
```

Подробно: [docs/architecture.md](docs/architecture.md). Что ловится и что нет:
[docs/threat_model.md](docs/threat_model.md).

Ключевые решения:

- **Уникальные приманки.** Фейковые секреты вида `CANARY-<uuid4>` генерируются заново на каждый
  запуск. Если такая строка всплыла в аргументах `execve`, совпадение исключено.
- **Сети нет вообще.** Контейнер запускается с `--network none`, поэтому соединение не состоится,
  но `strace` успевает записать сам вызов `connect()`.
- **Запускается копия.** В контейнер монтируется копия скила во временной папке — оригинал
  на хосте не меняется. На хост-машине скрипты скила не выполняются никогда.

## Установка

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и Docker с Linux-контейнерами.

```bash
uv sync
uv run skilltrap scan <путь-к-скилу>     # первый запуск соберёт образ песочницы
```

## Использование

```bash
uv run skilltrap scan <путь>                          # таблица в терминале
uv run skilltrap scan <путь> --format markdown -o report.md
uv run skilltrap scan <путь> --format json            # для CI
uv run skilltrap scan <путь> --keep-workspace ./dump  # оставить логи strace и fake_home
uv run skilltrap eval                                 # прогон всех фикстур
```

Коды выхода: `0` — SAFE, `1` — SUSPICIOUS, `2` — MALICIOUS, `3` — ошибка запуска.

## Что детектируется

| Уровень | Правило | Когда |
|---|---|---|
| CRITICAL | `canary-file-read` | открыт файл-приманка (`.env`, `.ssh/id_rsa`, `.aws/credentials`) |
| CRITICAL | `canary-value-leak` | значение приманки попало в аргументы другого вызова |
| HIGH | `network-connect` | `connect()` по AF_INET/AF_INET6 |
| HIGH | `suspicious-exec` | запуск `curl`, `wget`, `nc`, `ssh`… или оболочки с `-c` |
| HIGH | `persistence-write` | запись в `CLAUDE.md`, `AGENTS.md`, `.bashrc`, `.profile` |
| MEDIUM | `write-outside-workdir`, `file-deleted`, `home-file-*`, `script-timeout` | запись вне рабочей папки, удаление файлов, изменения в fake_home, таймаут |
| LOW / INFO | `invisible-unicode`, `base64-blob`, `hidden-executable` | статические проверки |

## Ограничения

- **Prompt injection не ловится.** Вредоносные инструкции в тексте `SKILL.md` исполняет агент,
  а не интерпретатор, поэтому в `strace` они не видны.
- **Один прогон.** Скил с отложенным срабатыванием (по дате, по числу запусков) не проявится.
- **Песочницу можно распознать.** Скил может заметить контейнер и вести себя тихо.
- **Только `.py` и `.sh`.**
- Подробнее: [docs/threat_model.md](docs/threat_model.md).

## Безопасность

- Контейнер: `--network none`, не root (uid 1000), `--memory 256m`, `--cpus 1.0`,
  `--pids-limit 128`, `--cap-drop ALL`, `--security-opt no-new-privileges`, таймаут 30 с.
  Единственная добавленная привилегия — `SYS_PTRACE` для `strace`.
- Настоящих ключей в репозитории нет: в шаблоне `fake_home` лежат только плейсхолдеры,
  отдельный тест это проверяет.
- Фикстуры в `fixtures/malicious/` **имитируют** атаки: читают приманки, пишут файлы внутри
  песочницы, стучатся на `127.0.0.1`. Никакой реальной отправки данных и загрузок из интернета.

## Roadmap

1. **Агент в контуре** — запустить ИИ-агента без интерфейса внутри песочницы с установленным
   скилом и нейтральной задачей, чтобы ловить вредоносные инструкции в тексте.
2. **GitHub Action** — проверка скилов в CI.
3. **Объединение со статическими сканерами** в один отчёт.
4. **Поддержка `.js`** и профили «нормального» поведения по системным вызовам.
