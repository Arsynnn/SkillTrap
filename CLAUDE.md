# CLAUDE.md — SkillTrap

## О проекте

**SkillTrap** — поведенческая песочница для проверки скилов ИИ-агентов (формат SKILL.md, стандарт agentskills.io).

Статические сканеры (Cisco skill-scanner, Snyk Agent Scan) смотрят, как скил *выглядит*, и их можно обойти (техника SkillCloak: нагрузка прячется в `.git/` и распаковывается только при запуске). SkillTrap смотрит, что скил *делает*:
запускает его скрипты в изолированном Docker-контейнере с «приманками» (фейковые ключи, SSH, `.env`), трассирует системные вызовы через `strace` и сообщает, если скил читает секреты, лезет в сеть, запускает подозрительные программы или пытается закрепиться в `CLAUDE.md` / `AGENTS.md` / `.bashrc`.

Автор — студент, проект одновременно учебный. **Объясняй ключевые решения коротко (1–3 предложения) и не пиши больше, чем просят в текущем шаге.**

## Правила безопасности (ОБЯЗАТЕЛЬНО)

1. Контейнер всегда запускается с `--network none`, не от root, с лимитами CPU/памяти и таймаутом.
2. Приманки — только сгенерированные фейковые значения вида `CANARY-<uuid>`. Никаких настоящих ключей нигде в репозитории.
3. Тестовые «вредоносные» фикстуры в `fixtures/malicious/` **только имитируют** поведение: читают приманки, пишут в файлы внутри песочницы, пытаются подключиться к `127.0.0.1`. Никакой реальной отправки данных, никаких реальных вредоносных нагрузок, никаких загрузок из интернета.
4. Не скачивать и не запускать настоящие вредоносные скилы из интернета.
5. Скрипты проверяемого скила никогда не выполняются на хост-машине — только в контейнере.

## Стек

- Python 3.11+ (весь код проекта — на Python)
- `uv` — окружение и зависимости
- `typer` — CLI, `rich` — вывод в терминал
- `pydantic` — модели данных (события, находки, отчёт)
- `pyyaml` — frontmatter SKILL.md
- `docker` (Docker SDK for Python) или `subprocess` + CLI docker — запуск песочницы
- `pytest` — тесты, `ruff` — линтер и форматтер
- Вне Python: `Dockerfile` (конфигурация образа) и `strace` (внешняя утилита внутри контейнера, вызывается из Python)

## Как работает сканирование (конвейер)

1. `loader` читает скил, валидирует frontmatter (`name`, `description`), находит все скрипты (`.py`, `.sh`), **включая скрытые папки**.
2. `static_checks` выполняет быстрые статические проверки (не главное, бонус).
3. `canaries` генерирует уникальные значения, `fsdiff` снимает хеши fake_home.
4. `runner` запускает каждый скрипт в контейнере:
   `strace -f -tt -s 256 -o /trace/<script>.log -e trace=openat,execve,connect,unlinkat,renameat2 <interpreter> <script>`
   Флаги контейнера: `--network none`, `--user 1000`, `--memory 256m`, `--pids-limit 128`, таймаут 30 с.
   Если strace падает с ошибкой прав, добавить `--cap-add=SYS_PTRACE`.
5. `trace_parser` превращает логи в `TraceEvent`.
6. `rules` выдаёт находки:
   - **CRITICAL** — чтение файла-приманки или появление значения `CANARY-` в аргументах `execve`/`connect`
   - **HIGH** — попытка `connect` к любому адресу; запуск `curl`, `wget`, `nc`, `bash -c`, `python -c`; изменение `CLAUDE.md`, `AGENTS.md`, `.bashrc`, `.profile`
   - **MEDIUM** — файлы, созданные вне рабочей папки; удаление файлов
   - **LOW / INFO** — находки статических проверок
7. `report` выводит вердикт (`SAFE` / `SUSPICIOUS` / `MALICIOUS`) и список находок с доказательствами (строка лога).

Важно: интерпретатор Python при старте читает много системных файлов. Правила должны реагировать на **пути приманок и конкретные действия**, а не на любой `openat`.

## Команды

```bash
uv sync                                   # установить зависимости
uv run skilltrap scan fixtures/malicious/reads_env_canary
uv run skilltrap scan <path> --format json
uv run skilltrap eval                     # прогон всех фикстур
uv run pytest
uv run ruff check . && uv run ruff format .
```

## Стиль кода

- Идентификаторы, имена файлов и коммитов — на английском; комментарии и docstring — можно на русском.
- Type hints везде, модели — через pydantic.
- Маленькие функции, без глобального состояния.
- Каждый модуль покрыт хотя бы одним тестом. Парсер strace тестируется на сохранённых логах из `tests/data/`, без Docker.
- Коммиты — в стиле Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`).

## Порядок работы

1. Прежде чем писать код нового модуля — кратко опиши план и дождись подтверждения.
2. Делай по одному модулю за шаг, в порядке:
   `models` -> `loader` -> `canaries` + `fake_home` -> `Dockerfile` + `runner` -> `trace_parser` -> `rules` -> `fsdiff` -> `report` -> `cli` -> фикстуры -> `eval` -> `static_checks` -> `SKILL.md` -> README.
3. После каждого модуля: тесты, `ruff`, коммит.
4. Не добавляй зависимости без необходимости.

## Определение «готово» для MVP

- `skilltrap scan` работает на всех фикстурах и выдаёт отчёт.
- Все 5 вредоносных имитаций обнаружены, «чистые» скилы получают `SAFE` (или ложные срабатывания объяснены в README).
- `eval/results.md` содержит таблицу с precision/recall.
- README: проблема (со ссылками на исследования), архитектура, демо (GIF/скриншот отчёта), результаты, ограничения, roadmap.
